# Migrating from the 1.x layout

The pre-refactor code is preserved in git at commit
[`86194c8`](https://github.com/Buycar-arb/ToolForge/commit/86194c8) — nothing was
lost. To look at any old file:

```bash
git show 86194c8:Stage_3/processors/case_processors.py
git checkout 86194c8 -- Stage_3/            # restore a whole directory
```

The old tool bank path still works: `toolforge/config.py` falls back to
`Stage_3/tool_bank/tools/` when `tool_bank/` is absent, so a stale checkout does
not break.

## Command equivalents

| 1.x | 2.x |
|-----|-----|
| edit paths at the top of `llm_generate_label.py`, then `python -m Stage_2.code.llm_generate_label` | `toolforge label IN OUT --limit N` |
| edit `MODEL`/`target` in `generate_tool.py`, then `python -m Stage_1.generate_tool` | `toolforge variants TOOL.json OUT --target N` |
| edit `c_cases_config` in `generate_and_judge_main.py`, then `python -m Stage_3.generate_and_judge_main` | `toolforge generate LABELS --case case_C1 --target N` |
| `python ToolForge_gradio_webui/quick_fast.py` | `toolforge webui` |
| `cd <dir> && python parquet_to_jsonl.py` | `toolforge convert to-jsonl <dir>` |
| — | `toolforge doctor`, `toolforge cases`, `toolforge validate` |

No stage needs source edits any more. Everything that used to be a module-level
constant is a CLI flag or a `.env` variable.

## Configuration

`.env` replaces the scattered constants. The old names still work:

| old | new | note |
|-----|-----|------|
| `API_KEYS` | `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` | `API_KEYS` is still read as a fallback for both |
| `API_BASE_URL` | `OPENAI_BASE_URL` | old name still read |
| `DEFAULT_MODEL` | `GENERATION_MODEL` | old name still read |
| `JUDGE_MODEL` | `JUDGE_MODEL` | unchanged |
| `SENTENCE_TRANSFORMER_MODEL_PATH` | `EMBEDDING_MODEL_PATH` | old name still read |

Run `toolforge doctor` to see what actually resolved.

## The data format is unchanged

Records written by 2.x are byte-compatible with 1.x: the same seven-element
list, the same field names, the same ordering. Data generated by either version
validates under either version, and training scripts need no changes.

## Behaviour

Identical by default — see [`behaviour-notes.md`](behaviour-notes.md) for the
two checks that were inert in 1.x and are preserved that way unless you opt in.
